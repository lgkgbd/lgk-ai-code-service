# 单词记忆功能 · 开发与测试计划

> 版本：v1 草案
> 关联文件：建表脚本 `sql/word_memory.sql`、前端原型 `docs/单词记忆功能-前端原型.html`、开发提示词 `docs/单词记忆功能-开发提示词.md`

---

## 一、产品定位

**记录我平时遇到的、不会的单词，方便以后回头看。**

跟扇贝 / 墨墨这类「背词库」产品的本质区别：核心资产不是单词本身，而是**「我在哪、什么时候、因为哪句话被这个词卡住了」**。上下文是记忆锚点，也是「回头看」的价值来源。

由此推出两条贯穿始终的设计原则：

1. **录入阻力必须接近零** —— 生词本类工具死于录入麻烦，不死于功能不够。用户只负责给一个词，其余全是系统的事。
2. **上下文由渠道自动带，不让用户填** —— 用户填不动，也不会填。

## 二、已定技术决策

### 2.1 词典数据源：ECDICT 本地库，一期不接 AI

采用 [ECDICT](https://github.com/skywind3000/ECDICT)（MIT，76 万词条，提供 MySQL 格式）导入本地数据库。

| 需求 | ECDICT 字段 | 说明 |
|---|---|---|
| 音标 | `phonetic` | |
| 中文释义 | `translation` | |
| 英文释义 | `definition` | 英英双解白送 |
| 词性 | `pos` | 带占比 |
| **六级词书** | **`tag`** | `cet4/cet6/ky/toefl/ielts/gre`，**一句 SQL 生成词书，无需另外导词表** |
| **词形还原** | **`exchange`** | 粘 `running` 认得 `run` |
| 难度分级 | `frq` / `bnc` | 词频排名 |
| 重要度 | `collins` / `oxford` | 柯林斯星级、牛津核心词 |

**收益：零 HTTP 调用、零延迟、零限流、零成本、零幻觉。** 录入即秒出完整卡片，一期整条链路砍掉 MQ / 异步补全 / 补偿 job。

> 已排除的方案：百度翻译 API 是**翻译**接口不是**词典**接口，传单词只回一个中文词，无音标/词性/多义项；有道词典 API 不支持控制台自助开通，需工作日电话或邮件联系商务，个人项目不划算。

### 2.2 AI 的定位：三期增值，不进主链路

| 词典库负责（客观） | 仅 AI 能做（三期） |
|---|---|
| 音标、词性、中英释义、通用例句 | 结合**你那句原句**的私人助记 |
| 词形变化、词频、考试标签 | 词源故事 |
| 同反义词 | 易混词对比卡（adapt/adopt/adept） |
| | 「用我今天的 8 个生词写一篇短文」 |
| | 「把这周生词生成一个闪卡小游戏」← 复用平台代码生成能力，独有卖点 |

### 2.3 数据模型：四层 + 一条铁律

```
word_dict            客观层  词是什么（全站共享）
word_book / _item    词书层  词的集合（生词本 = type=0 的一条记录）
user_book            订阅层  我在学哪几本
user_word            学习层  我的掌握状态  ★ unique(userId, dictId) ★
user_word_sighting   上下文  我在哪句话撞见过它
```

**铁律：`user_word` 对 `(userId, dictId)` 全局唯一，绝不用 `type` 字段区分「生词 / 六级」。**

理由：`serendipity` 既可能是你遇到的生词，又在六级词表里。用 type 字段会产生两条记录 → 两套掌握度 → 两条复习曲线 → 同一个词背两遍且进度互不相认。正确的抽象是「我对这个词的掌握」全局唯一，「词从哪来」是多对多。

**推论：生词本不是特例，它就是 `word_book(type=0)` 的一个实例。** 以后加雅思 / GRE / 专业术语表都是插数据，不改代码。两类词书唯一的差异是入池方式：

- 生词本 = push：录入即入池，`dailyNewLimit = -1`
- 预置词书 = pull：每天从 `learnCursor` 往后取 `dailyNewLimit` 个新词入池（字段不叫 `cursor`，那是 MySQL 保留字）

### 2.4 复习：统一队列，一期简化 SM-2

- 所有词书**共用一个复习队列**。首页只出现「今天要复习 37 个词」一个入口，**不分 tab**——分了用户就只点其中一个。
- 队列走 Redis ZSet `word:due:{userId}`，score = dueTime 时间戳，取当日待复习 O(logN)。Redis 挂了用 `idx_user_due` 索引回源 DB。
- 一期算法：简化 SM-2，作答质量四档，间隔梯度 `1 / 2 / 4 / 7 / 15 / 30 / 60 天`。`easeFactor` 字段已在表里预留，二期换标准 SM-2 或 FSRS 不需要改表。

### 2.5 五个默认值（**请确认，不同意直接改这一节**）

| # | 项 | 采用值 | 理由 | 备选 |
|---|---|---|---|---|
| 1 | ECDICT 导入量 | **全量 76 万词** | 生词本场景下**生僻词恰恰是重点**，遇到不会的词往往就是低频词。导子集会频繁出现「查不到」 | 只导 `frq>0 or tag非空`（约 5 万），省几百 MB |
| 2 | MVP 是否上 AI | **不上** | 砍掉 MQ / PENDING 状态 / 轮询 / 补偿 job，链路简化一大截，且体验更好（秒出 vs 异步补全） | 一期就接，多约 3 人天 |
| 3 | 前端入口 | **导航栏加「单词」，位于「交流」之后，`access = USER`** | 高频功能，藏进个人主页会用不起来 | 收进 `/user/profile` |
| 4 | 书签小工具 | **一期做** | 它是「零阻力」和「有上下文」能同时成立的唯一办法，成本仅一个接口 + 20 行脚本 | 挪到二期 |
| 5 | 复习算法 | **简化 SM-2** | 字段已预留，随时可升级 | 标准 SM-2 / FSRS |

## 三、录入设计（一期重点）

### 3.1 一个输入框，什么都能粘

| 粘进去的内容 | 系统行为 |
|---|---|
| `serendipity` | 建一张卡 |
| `adapt, adopt, adept` | 按逗号/换行/空格/分号拆，建 3 张 |
| `running` | `exchange` 还原到 `run`，卡片标注「原形 run」 |
| 一整句英文 | 挑出其中的生词，并把整句存为 sighting |
| 已存在的词 | **不新建**，`encounterNum + 1`，追加一条 sighting，提示「这词你第 3 次记了 👀」 |

交互补充：

- 页面级 `paste` 事件监听 —— 进页面 `Ctrl+V` 直接录入，**不用先点输入框**
- 回车即提交，乐观 UI：卡片立刻插到列表顶部
- 单次批量上限 50 词，超出提示分批

### 3.2 上下文三级兜底

| 入口 | 上下文来源 | `channel` |
|---|---|---|
| 浏览器书签小工具 | 脚本自动抓：选中词 + 所在整句 + `document.title` + URL | `bookmarklet` |
| 站内粘整句 | 自动拆词 + 留句 | `paste` |
| 只粘一个词 | 无 sighting，复习时用词典例句兜底 | `manual` |

书签小工具形态：一行 `javascript:` 书签，零安装、跨浏览器、手机可用，后续可平滑升级成 Chrome 插件。

### 4.4 核心逻辑要点

**capture 流程**（`WordService#capture`）

```
1. WordTextParser 拆分入参 → List<String> 候选词（去重、转小写、剔除标点）
2. 逐词：
   a. 查 word_dict（先原形，再用 exchange 反查还原形）
   b. 未命中 → 走 Enricher 责任链 → insert word_dict
   c. 查 user_word (userId, dictId)
      - 存在 → encounterNum + 1
      - 不存在 → insert，mastery=0，dueTime=now（立即可复习）
                 同时插 word_book_item 到该用户的生词本
   d. 有 sentence 则插一条 user_word_sighting
   e. 写 Redis ZSet word:due:{userId}
3. 返回 List<WordCardVO>，标注每个词是「新增」还是「第 N 次遇见」
```

并发安全：`user_word` 的唯一索引 `uq_user_dict` 是最终防线，捕获 `DuplicateKeyException` 后转为 `encounterNum + 1`，不要依赖「先查后插」。

**review submit 流程**

```
1. 校验 userWordId 属于当前用户
2. Sm2Calculator 依据 quality 算出新的 intervalDays / easeFactor / dueTime
3. 更新 user_word，写 user_word_review_log
4. 更新 Redis ZSet score；quality=0（完全忘记）则 dueTime=今天，重新入队
5. 连续答对且 intervalDays >= 60 → mastery=3 已掌握，移出复习池
```

### 6.2 服务层测试

| 场景 | 断言 |
|---|---|
| 首次录入新词 | `user_word` 新增 1 条，`encounterNum=1`，`mastery=0`，Redis ZSet 有该成员 |

| 提交复习 quality=0 | `dueTime` 回到当天，`lapseCount+1`，重新入队 |
| 连续答对至 `intervalDays>=60` | `mastery=3`，移出 Redis 队列 |
| 跨用户越权 | A 用户提交 B 用户的 `userWordId` → `NO_AUTH_ERROR` |
| 六级词书订阅（二期） | 每日只投放 `dailyNewLimit` 个新词；`learnCursor` 正确推进；跨天重置配额 |
| **同一个词既在生词本又在六级书** | **`user_word` 仍只有 1 条**，复习进度共享 ← 核心回归用例 |

## 八、风险与注意事项

| 风险 | 应对 |
|---|---|
| ECDICT 全量导入体积（数百 MB） | 先在本地验证导入耗时与磁盘占用；若不可接受，退回决策 #1 的备选（只导 `frq>0 or tag非空`） |
| ECDICT 数据授权 | 代码 MIT；词典数据整合自多个来源，若日后要商用需自行核实各来源许可 |
| 词形还原不完美 | `exchange` 覆盖不了全部情况（专有名词、缩写、短语）。策略：还原失败就按原样建词，不阻断录入 |
| 书签小工具受 CSP 限制 | 部分站点（如 GitHub）CSP 会拦截 `javascript:` 书签。策略：文档里说明，并保留站内手动粘贴入口 |
| 跨域 Cookie | 书签小工具从任意站点提交，需服务端配置 CORS 白名单 + `withCredentials`；或改用带 token 的 URL 跳转方式 |
| 复习日志表增长 | `user_word_review_log` 量最大，二期上线时同步规划归档策略 |
| 与已有导航的耦合 | 「单词」菜单项 `access=USER`，未登录不展示；`GlobalHeader` 的权限过滤已支持，无需改动组件 |

## 九、明确不做

- **不做四六级词表强制导入式主流程** —— 会稀释「记录我遇到的词」这个内核，退化成又一个背词 App。词书是可选订阅，不是默认入口。
- **不设每日强制任务量 / 不做断签惩罚** —— 生词本是低压力工具，一旦有 KPI 感就会被弃用。
- **不做复习队列分 tab** —— 见 2.4。
