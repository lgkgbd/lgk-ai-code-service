## 前置准备（人工做，不要让 AI 代劳）

1. 下载 ECDICT 数据。**不要下 release 里的 `ecdict-sqlite-28.zip`（216MB）**，
   直接下仓库主分支的 `ecdict.csv`（66MB）：

   ```bash
   curl -L --progress-bar -o ecdict.csv https://gh-proxy.com/https://raw.githubusercontent.com/skywind3000/ECDICT/master/ecdict.csv
   ```

   实测速度：gh-proxy.com 862KB/s > ghfast.top 363KB/s >
   github.com/raw 40KB/s > raw.githubusercontent.com 13KB/s。
   Gitee 镜像有防盗链会 Access denied，jsDelivr 超文件大小限制返回 403，都别用。

   下完核对：约 66MB、约 77 万行、表头 13 列

   ```bash
   ls -lh ecdict.csv && wc -l ecdict.csv && head -1 ecdict.csv
   ```

2. 导入 MySQL，表名 `stardict`。**必须导进项目自己的库 `lgk_ai_code_service`**，
   不要另建库，否则 EcdictEnricher 跨库查不到。
   建表 DDL 和 `load data` 命令见 `sql/word_memory.sql` 开头的 Step 0.1 / 0.2。

   ⚠️ 执行建表脚本必须带 `--default-character-set=utf8mb4`，否则中文注释和
   词书名会存成双重编码乱码，而且用同样缺参数的客户端查回来还看不出来：

   ```bash
   mysql --local-infile=1 --default-character-set=utf8mb4 -uroot -p lgk_ai_code_service < sql/word_memory.sql
   ```

3. 验证，三条都要有正常结果：

   ```sql
   select count(*) from stardict;                          -- 约 77 万
   select count(*) from stardict where tag like '%cet6%';  -- 约 5000
   select word, phonetic, translation, exchange from stardict where word = 'meticulous';
   ```

4. 确认本地 MySQL / Redis 已启动，后端能正常跑起来

# 提示词正文

## ══════ 第 1 段：数据层 + 核心工具类 ══════

```
我要在这个项目里开发一个「单词记忆」功能。请先阅读这三份已有文档，它们是本次开发的唯一依据：

- docs/单词记忆功能-开发计划.md   （设计决策、接口清单、测试计划，必读）
- sql/word_memory.sql             （建表脚本，已写好）
- docs/单词记忆功能-前端原型.html （视觉原型，第 3 段才用）

本段只做数据层和两个核心工具类，不要写 Controller，不要碰前端。

任务：

1. 执行 sql/word_memory.sql 建表（ECDICT 的 stardict 表我已经手动导好了，不要动它）

2. 用 MyBatis-Flex 的代码生成或手写，创建 7 张表对应的 entity 和 mapper：
   WordDict / WordBook / WordBookItem / UserBook / UserWord / UserWordSighting / UserWordReviewLog
   严格对齐 model/entity/Comment.java 的写法：
   @Data @Builder @NoArgsConstructor @AllArgsConstructor @Table("表名")
   @Id(keyType = KeyType.Generator, value = KeyGenerators.snowFlakeId)
   驼峰列名要加 @Column("xxx")

3. 创建枚举 model/enums/：
   MasteryEnum(0新词/1学习中/2复习中/3已掌握)
   ReviewQualityEnum(0完全忘记/1模糊/2想起来了/3秒答)
   WordBookTypeEnum(0个人生词本/1系统预置)
   WordSourceEnum(ecdict/api/ai/manual)
   参考 model/enums/ 下已有枚举的写法

4. 实现 utils/WordTextParser.java —— 把用户粘贴的任意文本拆成候选单词列表：
   - 支持逗号 / 分号 / 换行 / 空格 / 顿号 分隔
   - 去重、trim、转小写、剔除首尾标点
   - 只保留纯英文字母（含连字符和撇号，如 well-known、don't）
   - 单次上限 50 个，超出截断并在返回值里标记
   - 输入是整句英文时同样按空格拆词（生词筛选交给上层，本类只负责拆）
   - 词形还原：给一个 restoreLemma(String word) 方法，
     查 stardict.exchange 字段（格式形如 "p:ran/d:run/i:running/3:runs"），
     反查出原形。查不到就返回原词，绝不抛异常阻断录入。

5. 实现 utils/Sm2Calculator.java —— 简化版 SM-2：
   入参：当前 easeFactor、intervalDays、reviewCount、本次 quality
   出参：新的 easeFactor、intervalDays、dueTime
   规则：
   - 间隔梯度 1 / 2 / 4 / 7 / 15 / 30 / 60 天
   - quality=0 完全忘记 → intervalDays 归 1，今天重来，easeFactor -= 0.20
   - quality=1 模糊     → 间隔梯度退一级，easeFactor -= 0.10
   - quality=2 想起来了 → 间隔梯度进一级，easeFactor 不变
   - quality=3 秒答     → 间隔梯度进两级，easeFactor += 0.10
   - easeFactor 下限 1.3，上限 2.8，必须做钳制
   - intervalDays >= 60 且连续答对 → 标记可毕业（返回一个 canGraduate 标志）

6. 给 WordTextParser 和 Sm2Calculator 写 JUnit 5 单元测试，
   用例清单见 docs/单词记忆功能-开发计划.md 的 6.1 节，一条都不要漏。
   特别注意 easeFactor 下限 1.3 不能被击穿这条。

7. 在 constant/ 下加 WordConstant，并在 RedisConstant 里追加 word:* 系列 key
   （key 命名见 sql/word_memory.sql 文件末尾的约定，照抄 RedisConstant 现有的
    静态方法写法）

做完后跑一遍 mvn test，把测试结果贴给我。
```

## ══════ 第 2 段：Service + Controller ══════

```
继续单词记忆功能，第 1 段的数据层和工具类已完成。本段做后端业务层，仍然不要碰前端。

1. 词条补全责任链 service/word/enricher/：

   public interface WordEnricher {
       int order();
       boolean supports(String lang);
       Optional<WordDictInfo> enrich(String spelling);
   }

   - EcdictEnricher(order=0)：查本地 stardict 表，命中则映射成 WordDict。
     注意 word_dict.extInfo 是 json，把 collins/oxford/detail 之类塞进去
   - FreeDictionaryEnricher(order=10)：调 https://api.dictionaryapi.dev/api/v2/entries/en/{word}
     免费无需 key。必须设 3 秒超时 + 异常吞掉返回 empty，绝不能因为它挂了阻断录入
   - 用 Spring 注入 List<WordEnricher>，按 order 排序依次尝试，命中即返回
   - 全都没命中 → 建一条 source='manual' 的占位词条，不要抛异常

2. WordService#capture(WordCaptureRequest, User) —— 录入主链路，本功能最核心的方法：

   流程严格按 docs/单词记忆功能-开发计划.md 的 4.4 节实现。

   三个必须做对的点：
   a) 幂等：同一个词重复录入不新建 user_word，而是 encounterNum + 1
   b) 并发安全：不要用「先 select 再 insert」判重，必须依赖
      user_word 的唯一索引 uq_user_dict，catch DuplicateKeyException
      之后转成 encounterNum + 1 的 update
   c) 返回值要能区分每个词是「新增」还是「第 N 次遇见」，前端要用这个做提示

   录入成功后写 Redis ZSet word:due:{userId}，score = dueTime 时间戳。
   新词 dueTime = now，也就是立刻可复习。

3. WordReviewService：
   - getTodayQueue(userId)：从 Redis ZSet 取 score <= now 的成员。
     Redis 无数据时用 idx_user_due 索引回源 DB 并重建缓存
   - submit(userWordId, quality, costMs, loginUser)：
     先校验 userWordId 属于当前用户，不属于就抛 NO_AUTH_ERROR；
     调 Sm2Calculator 算新状态 → 更新 user_word → 写 user_word_review_log
     → 更新 Redis ZSet score；
     canGraduate 时 mastery 置 3 并从 ZSet 移除

4. WordDictService：查词、按 spelling 搜索联想

5. Controller 层，接口清单见开发计划 4.3 节标「一」期的那些。
   严格对齐 controller/PostFavourController.java 的风格：
   @RestController + @RequestMapping("/word")
   统一 BaseResponse + ResultUtils.success()
   参数校验用 ThrowUtils.throwIf + ErrorCode
   登录用 userService.getLoginUser(request)

6. 书签小工具接口 GET /word/bookmarklet/script：
   返回一段 javascript 字符串，功能是：
   - 取 window.getSelection() 选中的词
   - 取选中词所在的整句（向前后找到最近的 . ! ? 边界）
   - 带上 document.title 和 location.href
   - POST 到 /api/word/capture，channel='bookmarklet'
   - 用 fetch + credentials:'include'
   同时在 config/ 里给 CORS 加上必要配置，让任意来源能带 cookie 调这个接口
   （如果现有 CORS 配置不允许，就改成先跳转到站内页面再提交的方式，
     跳转方案更安全，你判断哪种合适，做之前先告诉我你的选择和理由）

7. 按开发计划 6.2 节的场景写服务层测试。
   最重要的两条回归用例一定要有：
   - 重复录入同一个词，user_word 只有 1 条，encounterNum = 2
   - 同一个词既在生词本又在六级词书里，user_word 仍然只有 1 条

做完跑 mvn test 并用 curl 或 HTTP 文件把每个接口都调通一遍，把结果贴给我。
```

   代码路径必须和系统词书完全共用。

   录入必须是同步秒返回的。
